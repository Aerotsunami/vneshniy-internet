# Контракт ежедневной автоматизации

Автоматизация должна создавать один файл `content/issues/YYYY-MM-DD.json` и открывать pull request. Она не должна напрямую менять основную ветку.

Обязательная последовательность:

1. Найти и проверить материалы.
2. Сравнить темы с тремя предыдущими файлами архива.
3. Сформировать до 10 материалов, но не добирать выпуск слабыми или повторными темами.
4. Выполнить `npm run content:check`.
5. Открыть pull request с названием `Выпуск за YYYY-MM-DD`.

После проверки редактор объединяет pull request. GitHub Pages публикует выпуск автоматически.

## Идентификаторы

`materials[].id` должен быть коротким, состоять из латинских букв, цифр и дефисов и не повторяться во всем архиве. Он используется в постоянной ссылке на материал.

## Источники

Каждый источник содержит название, HTTPS-ссылку и дату в формате `YYYY-MM-DD`. Текст выпуска хранится в `body` как массив из 3–6 абзацев. Поле `check` содержит только факты, которые стоит перепроверить перед публикацией.
